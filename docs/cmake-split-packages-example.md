# A converted project, side by side with its CMakeLists

This is a **worked example**: a small but realistic CMake project shown
next to what `convert-element-cmake` emits for it. The goal is to make
the converter's output legible by anchoring it to a CMake layout you
already know how to read.

The project used here is the committed fixture
[`converter/testdata/sample-projects/subdir-library`](../converter/testdata/sample-projects/subdir-library)
— the same one the `scripts/meta-cmake-split-packages.sh` render gate
drives. Everything below is **real converter output**, not a sketch; you
can regenerate it yourself (see [Reproducing this](#reproducing-this)).

The focus is the `--split-packages` (a.k.a. "gazelle model") emit, which
mirrors the `CMakeLists.txt` / `add_subdirectory()` directory layout —
one `BUILD.bazel` per directory. For the mechanism and its v1
boundaries, see the design doc
[`docs/design/cmake-split-packages.md`](design/cmake-split-packages.md);
this page is the example that doc points at.

## The CMake project

A two-library project: a top-level `toplib` that depends on a `util`
library declared in a sub-directory, with the public headers in a shared
`include/` root. It installs both libraries plus a CMake config package
(`install(EXPORT)`).

Source tree:

```
subdir-library/
├── CMakeLists.txt            # project(); add_subdirectory(src/util); add_library(toplib)
├── include/
│   ├── toplib.h
│   └── util.h
└── src/
    ├── toplib.c
    └── util/
        ├── CMakeLists.txt    # add_library(util)
        └── util.c
```

The two `CMakeLists.txt` files:

**`CMakeLists.txt`** (root)

```cmake
cmake_minimum_required(VERSION 3.20)
project(toplib LANGUAGES C VERSION 0.1.0)

add_subdirectory(src/util)

add_library(toplib STATIC src/toplib.c)
target_include_directories(toplib PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:include>)
target_link_libraries(toplib PUBLIC util)

install(TARGETS toplib util
        EXPORT toplibTargets
        ARCHIVE DESTINATION lib)
install(DIRECTORY include/ DESTINATION include)
install(EXPORT toplibTargets
        FILE toplibTargets.cmake
        NAMESPACE toplib::
        DESTINATION lib/cmake/toplib)
```

**`src/util/CMakeLists.txt`**

```cmake
add_library(util STATIC util.c)
target_include_directories(util PUBLIC
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/../../include>
    $<INSTALL_INTERFACE:include>)
```

## The converted project (`--split-packages`)

The converter emits one `BUILD.bazel` per directory, so the Bazel tree
lines up with the CMake tree directory-for-directory:

```
CMake source tree                    Converted Bazel tree
─────────────────────────            ──────────────────────────────────
subdir-library/                      elements/subdir-library/
├── CMakeLists.txt          ───────► ├── BUILD.bazel        (toplib + installs)
├── include/                ───────► ├── include/
│   ├── toplib.h                     │   └── BUILD.bazel     (include_headers)
│   └── util.h                       │
└── src/                             └── src/
    ├── toplib.c                         └── util/
    └── util/              ───────►          └── BUILD.bazel (util)
        ├── CMakeLists.txt
        └── util.c
```

Walking it directory by directory, CMake input on the left, emitted
`BUILD.bazel` on the right:

### Root — `CMakeLists.txt` → `BUILD.bazel`

The root `add_library(toplib ...)` lands in the root package. Note what
the converter did with the three pieces of CMake state:

- `target_link_libraries(toplib PUBLIC util)` → a **cross-package label
  dep** `//elements/subdir-library/src/util` (the `util` target lives in
  its declaring directory's package).
- `target_include_directories(... include)` → a dep on the
  **synthesized header library** `//elements/subdir-library/include:include_headers`
  rather than a raw `includes = ["include"]` (see the `include/` package
  below).
- the three `install(...)` calls → root-pinned `filegroup` +
  `cc_import` facades (install-derived targets stay in the root package
  by design).

```python
# Generated by convert-element-cmake. DO NOT EDIT.

load("@rules_cc//cc:defs.bzl", "cc_import", "cc_library")

package(default_visibility = ["//visibility:public"])  # keep

# Source: CMakeLists.txt:10 (add_library)
cc_library(
    name = "toplib",
    srcs = ["src/toplib.c"],
    copts = ["-O3"],  # keep
    defines = ["NDEBUG"],  # keep
    linkstatic = True,  # keep
    deps = [
        "//elements/subdir-library/include:include_headers",
        "//elements/subdir-library/src/util",
    ],
)

filegroup(
    name = "cmake_config_bundle",
    srcs = ["lib/cmake/toplib/toplibTargets.cmake"],
)  # keep

cc_import(
    name = "toplib_import",
    static_library = "lib/libtoplib.a",
    tags = ["cmake-codegen-install-export-import"],
)  # keep

cc_import(
    name = "util_import",
    static_library = "lib/libutil.a",
    tags = ["cmake-codegen-install-export-import"],
)  # keep
```

### `src/util/CMakeLists.txt` → `src/util/BUILD.bazel`

The `add_library(util STATIC util.c)` from the sub-`CMakeLists.txt`
lands in the matching sub-package. Its `util.c` source is
**re-relativized** to the package (`"util.c"`, not
`"src/util/util.c"`), and its `target_include_directories(... ../../include)`
likewise resolves to a dep on the shared `include_headers` library:

```python
# Generated by convert-element-cmake. DO NOT EDIT.

load("@rules_cc//cc:defs.bzl", "cc_library")

package(default_visibility = ["//visibility:public"])  # keep

# Source: src/util/CMakeLists.txt:1 (add_library)
cc_library(
    name = "util",
    srcs = ["util.c"],
    copts = ["-O3"],  # keep
    defines = ["NDEBUG"],  # keep
    linkstatic = True,  # keep
    deps = ["//elements/subdir-library/include:include_headers"],
)
```

### `include/` → `include/BUILD.bazel`

There is no `CMakeLists.txt` under `include/` — this package is
**synthesized**. CMake's include semantics are a single `-I<root>` that
makes every header under the root reachable; to preserve that after the
split, the converter promotes the include root to its own package with a
header `cc_library` that globs the headers and re-exports the root via
`includes = ["."]`. Both `toplib` and `util` depend on it (above), so
`#include "toplib.h"` / `#include "util.h"` resolve exactly as they did
under CMake's `-Iinclude`:

```python
# Generated by convert-element-cmake. DO NOT EDIT.

# gazelle:cc_search "" elements/subdir-library/include

load("@rules_cc//cc:defs.bzl", "cc_library")

package(default_visibility = ["//visibility:public"])  # keep

cc_library(
    name = "include_headers",
    hdrs = [
        "toplib.h",
        "util.h",
    ],
    includes = ["."],  # keep
)
```

### Cross-element exports — `exports.json`

The cross-element export channel records the **sub-package label** for
each importable target, so a downstream element's
`find_package(toplib CONFIG)` resolves `toplib::util` to its real
package (`//elements/subdir-library/src/util:util`), not a flattened
root label:

```json
{
  "version": 1,
  "elements": [
    {
      "name": "toplib",
      "exports": [
        {
          "cmake_target": "toplib::toplib",
          "bazel_label": "//elements/subdir-library:toplib",
          "cmake_config_bundle_label": "//elements/subdir-library:cmake_config_bundle",
          "cmake_import_labels": [
            "//elements/subdir-library:toplib_import",
            "//elements/subdir-library:util_import"
          ]
        },
        {
          "cmake_target": "toplib::util",
          "bazel_label": "//elements/subdir-library/src/util:util",
          "cmake_config_bundle_label": "//elements/subdir-library:cmake_config_bundle",
          "cmake_import_labels": [
            "//elements/subdir-library:toplib_import",
            "//elements/subdir-library:util_import"
          ]
        }
      ]
    }
  ]
}
```

## For contrast: the single-`BUILD` (default) emit

`--split-packages` is opt-in. With it **off** (the default), the same
project converts to one monolithic `BUILD.bazel` at the element root
with element-root-relative source paths, a raw `includes = ["include"]`
on each target, and an intra-element `:util` dep. This is the
byte-identical-to-pre-feature output; it builds fine, it just doesn't
mirror the directory layout:

```python
# Generated by convert-element-cmake. DO NOT EDIT.

# gazelle:cc_search "" elements/subdir-library/include

load("@rules_cc//cc:defs.bzl", "cc_import", "cc_library")
load("@rules_pkg//pkg:mappings.bzl", "pkg_files", "strip_prefix")

package(default_visibility = ["//visibility:public"])  # keep

# Source: CMakeLists.txt:10 (add_library)
cc_library(
    name = "toplib",
    srcs = ["src/toplib.c"],
    copts = ["-O3"],  # keep
    defines = ["NDEBUG"],  # keep
    includes = ["include"],  # keep
    linkstatic = True,  # keep
    deps = [":util"],
)

# Source: src/util/CMakeLists.txt:1 (add_library)
cc_library(
    name = "util",
    srcs = ["src/util/util.c"],
    hdrs = [
        "include/toplib.h",
        "include/util.h",
    ],
    copts = ["-O3"],  # keep
    defines = ["NDEBUG"],  # keep
    includes = ["include"],  # keep
    linkstatic = True,  # keep
)

pkg_files(
    name = "install_directory__include",
    srcs = glob(["include/**"]),
    prefix = "include",
    strip_prefix = strip_prefix.from_pkg("include"),
)  # keep

filegroup(
    name = "cmake_config_bundle",
    srcs = ["lib/cmake/toplib/toplibTargets.cmake"],
)  # keep

cc_import(
    name = "toplib_import",
    static_library = "lib/libtoplib.a",
    tags = ["cmake-codegen-install-export-import"],
)  # keep

cc_import(
    name = "util_import",
    static_library = "lib/libutil.a",
    tags = ["cmake-codegen-install-export-import"],
)  # keep
```

Things to notice between the two emits:

| Aspect | Single `BUILD` (default) | `--split-packages` |
| --- | --- | --- |
| File layout | one root `BUILD.bazel` | one `BUILD.bazel` per directory |
| `util` source | `srcs = ["src/util/util.c"]` | `srcs = ["util.c"]` (re-relativized) |
| `toplib`→`util` dep | `:util` (same package) | `//elements/subdir-library/src/util` (label) |
| Headers / includes | `includes = ["include"]` + `hdrs` on the lib | synthesized `include:include_headers` lib, `includes = ["."]` |
| Install-derived targets | root package | root package (unchanged) |
| `exports.json` label for `util` | `//elements/subdir-library:util` | `//elements/subdir-library/src/util:util` |

The `# keep` markers are gazelle-stability annotations: they pin the
CMake-derived attributes (and whole install-derived rules) that
`gazelle_cc` can't re-derive from sources, so the layout survives a
`bazel run //:gazelle` maintenance pass. See the design doc's
[gazelle stability](design/cmake-split-packages.md#gazelle-stability)
section.

## Reproducing this

The output above came from running the converter against the committed
fixture in both modes:

```sh
make converter   # builds build/bin/convert-element-cmake

src=converter/testdata/sample-projects/subdir-library
pkg=elements/subdir-library

# --split-packages (the tree shown above)
build/bin/convert-element-cmake \
    --source-root "$src" \
    --split-packages \
    --bazel-package-path "$pkg" \
    --out-build /tmp/out/BUILD.bazel \
    --out-exports /tmp/out/exports.json
#   → /tmp/out/BUILD.bazel
#     /tmp/out/include/BUILD.bazel
#     /tmp/out/src/util/BUILD.bazel
#     /tmp/out/exports.json

# default single-BUILD emit (for contrast)
build/bin/convert-element-cmake \
    --source-root "$src" \
    --bazel-package-path "$pkg" \
    --out-build /tmp/off/BUILD.bazel
```

`convert-element-cmake` runs CMake's File API + `--trace-expand` to
configure the project, so it needs `cmake` + `ninja` on `$PATH`. The
`scripts/meta-cmake-split-packages.sh` render gate wraps exactly this
flow (both modes) and asserts the per-directory tree, the cross-package
labels, the synthesized header library, and the `exports.json`
sub-package label — and that `buildifier -mode=diff` is a no-op on every
emitted `BUILD`.
